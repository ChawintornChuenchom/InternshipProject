# ThaiOCRBench (200 ข้อ): Typhoon OCR vs Qwen3-VL-2B base vs Qwen3-VL-2B thaidoc

> ใช้เทียบ 3 โมเดลนี้กันเองเท่านั้น ห้ามเทียบตรง ๆ กับตัวเลขในเปเปอร์ (ดูหัวข้อข้อจำกัด)

## วิธีวัด

- ชุดข้อ: `scb10x/ThaiOCRBench` split test สุ่มแบบเดียวกับ `--max_samples` ของทางการ (map, `shuffle(seed=42)`, `select(range(200))`) ทุกโมเดลได้ 200 ข้อชุดเดียวกัน ลำดับเดียวกัน
- Prompt: ดึง lambda จาก `eval_scripts/run_inference.py` มาใช้ตรง ๆ (`"Instruction: " + question + "\nตอบเฉพาะข้อความตามภาพตรง ๆ อย่างกระชับ โดยไม่ใส่คำอธิบายเพิ่มเติม"`) ไม่มี system prompt
- Inference: Ollama `/api/chat` รูปเป็น base64 PNG, temperature 0, num_predict 4096, num_ctx 8192, seed 42, ย่อรูปให้ด้านยาวไม่เกิน 1,800 px (LANCZOS, ย่ออย่างเดียว ไม่ขยาย)
- ให้คะแนน: `eval_scripts/eval.py` ของทางการ ไม่ได้แก้ (รันด้วย `PYTHONUTF8=1` เพราะ eval.py เปิดไฟล์โดยไม่ระบุ encoding)
- Environment ของ eval: Python 3.12 venv แยก, ติดตั้งตาม requirements.txt ยกเว้น Polygon3 (build บน Windows ไม่ได้ และใช้แค่หมวด text spotting ภาษาอังกฤษที่ไม่อยู่ใน 13 หมวด) เพิ่ม pythainlp ที่ eval ใช้แต่ไม่อยู่ใน requirements และ pin `nltk==3.9.1` เพราะ nltk 3.10 เพิ่มเพดาน 2,000 ตัวอักษรใน `edit_distance` ทำให้ eval.py crash กับคำตอบยาว (สูตรคะแนนเหมือนเดิม)
- ค่าเฉลี่ยรวม = ค่าเฉลี่ยของ 13 หมวด (macro) ค่ากลุ่ม = ค่าเฉลี่ยของหมวดในกลุ่ม แบ่งกลุ่มตามฟังก์ชันที่ eval.py ใช้ให้คะแนน
  - TED: Table / Chart / Document parsing
  - BMFL (BLEU, METEOR, F1, 1-edit distance): Fine-grained text recognition, Full-page OCR, Handwritten content extraction
  - F1: Key information extraction / mapping
  - ANLS: Text recognition, Document classification, Diagram VQA, Cognition VQA, Infographics

### สรุป

- **Thaidoc ดีขึ้นเล็กน้อย แต่ยังสรุปไม่ได้ว่าดีกว่าจริง:** Thaidoc 0.381 vs Base 0.356 (+0.024) ช่วง CI −0.011 ถึง +0.062 คร่อม 0
- **ผล 100 ข้อแรกดูดีเกินจริง:** ตอน 100 ข้อได้ +0.058 และ CI ไม่คร่อม 0 พอเพิ่มเป็น 200 ข้อ ผลต่างลดลงเกินครึ่ง ให้ใช้รายงาน 200 ข้อนี้แทนฉบับ 100 ข้อ
- **คะแนนที่เพิ่มมาจากวนลูปน้อยลงทั้งหมด:** Base วนลูป 29 ข้อ, Thaidoc 13 ข้อ ข้อที่ Base วนแต่ Thaidoc ไม่วนมี 24 ข้อ ให้คะแนนเพิ่มรวม +4.86 ขณะที่ผลต่างรายข้อรวมทั้ง 200 ข้อคือ +4.16 แปลว่าอีก 176 ข้อที่เหลือ Thaidoc แย่กว่า Base เล็กน้อย (−0.70)
- **ความหมาย:** การเทรนช่วยให้โมเดลหยุดตอบได้ถูกที่ แต่ยังไม่ได้ทำให้อ่านเอกสารใน ThaiOCRBench แม่นขึ้น ต่างจากชุดทดสอบเอกสารสมมติของเราเองที่ CER ดีขึ้นชัด ซึ่งน่าจะเป็นเพราะเอกสารใน ThaiOCRBench หลากหลายกว่าข้อมูลเทรนมาก
- **ดีขึ้นในหมวด:** Full-page OCR +0.081 (16 ข้อ), Text recognition +0.059 (26), Fine-grained text recognition +0.050 (17), Document parsing +0.119 (7) ทั้งหมดเป็นหมวดที่วนลูปลดลง (Full-page OCR 6 เหลือ 2, Fine-grained 4 เหลือ 1, Text recognition 4 เหลือ 0)
- **หมวดที่ขึ้นว่า "ดีขึ้นชัด":** มีสองหมวดคือ Full-page OCR (ขอบล่างของ CI เฉียด 0) และ Fine-grained แต่วัดพร้อมกัน 13 หมวด จึงมีโอกาสที่หมวดหนึ่งจะดูต่างไปเองโดยบังเอิญ ให้ถือเป็นแค่สัญญาณ
- **แย่ลงในหมวด:** Key information extraction −0.090 (12 ข้อ) และ Key information mapping −0.044 (14) ทำให้กลุ่ม F1 ลดลง −0.067 น่าจะเป็นเพราะข้อมูลเทรนเป็นการถอดข้อความทั้งหน้า ไม่มีงานดึงข้อมูลเป็น key-value
- **เท่าเดิม:** Diagram VQA, Cognition VQA, Infographics, Handwritten content extraction

## ข้อจำกัด

- วัดแค่ 200 จาก 2,808 ข้อ (หมวดละประมาณ 15 ข้อ แต่สุ่มแล้วไม่เท่ากัน ตั้งแต่ 7 ถึง 26 ข้อ) คะแนนรายหมวดจึงแกว่งได้มาก ดูช่วง CI ประกอบ
- CI ในรายงานคิดจากการสุ่มข้อซ้ำ (bootstrap) ภายในชุดนี้ บอกความไม่แน่นอนจากการเลือกข้อ ไม่ได้รวมความแปรปรวนจากการรันซ้ำหรือจาก quantization
- ใช้โมเดล quantize ผ่าน Ollama (Typhoon Q4_K_M, Qwen q8_0) ไม่ใช่ bf16 ผ่าน vLLM แบบในเปเปอร์ และ Typhoon quantize หนักกว่าอีก 2 ตัว
- ย่อรูปให้ด้านยาวไม่เกิน 1,800 px และ num_predict 4096 (ทางการใช้ max_tokens 11000) คำตอบยาว ๆ ที่เกิน 4096 token จะถูกตัด
- รันครั้งเดียว (temperature 0) ไม่ได้วัดความแปรปรวนจากการรันซ้ำ
- ด้วยเหตุผลข้างบน **เทียบตรง ๆ กับตัวเลขในเปเปอร์ (arXiv 2511.04479) ไม่ได้** ใช้เทียบ 3 โมเดลนี้กันเองเท่านั้น
- eval.py ของทางการให้คะแนนหมวด ANLS เต็ม 1 ถ้าเฉลยเป็น substring ของคำตอบ คำตอบยาวที่บังเอิญมีเฉลยอยู่จึงได้เต็ม และ Document parsing ที่คำตอบว่างยังได้ประมาณ 0.05 (STEDS) ส่วน Table parsing (TEDS) ให้คะแนนติดลบได้เล็กน้อยเมื่อ HTML ที่ตอบยาวกว่าเฉลยมาก (เจอ 3 ข้อ ต่ำสุด -0.047) รายงานนี้ใช้คะแนนตามที่ eval.py ให้ ไม่ได้ปัดเป็น 0
- ThaiOCRBench ใช้เป็นชุดทดสอบเท่านั้น ไม่ได้ปนกับ `thai-doc-ocr/data/train`

- runner: `ThaiOCRBench/ollama_eval/run_ollama.py`, driver: `ollama_eval/run_all.ps1`, รายงาน: `ollama_eval/make_report.py`
- คำตอบดิบ (รูปแบบเดียวกับ run_inference.py): `ThaiOCRBench/ollama_pred/<model>_300.json` (+ `.meta.jsonl` เวลา/token ต่อข้อ) ชื่อไฟล์ยังเป็น _300 เพราะวางแผนไว้ 300 ข้อ แต่ข้างในมี 200 ข้อแรกของลำดับเดียวกัน รันต่อเป็น 300 ได้ด้วย `run_all.ps1`
- ผลจาก eval.py: `ThaiOCRBench/ollama_res/<model>_300.json` และ `.eval.txt`
